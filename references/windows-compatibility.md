# Windows Compatibility

Use this reference when running or validating `more-news-briefing` on Windows.

## Supported baseline

1. Windows 10 or Windows 11
2. PowerShell 5.1 or PowerShell 7
3. Python 3.10 or newer
4. A UTF-8 capable terminal; Windows Terminal is recommended but not required

The standalone runner uses only the Python standard library. Its core commands do not require Bash, WSL, GNU utilities, or executable-bit support.

## PowerShell quick start

Open PowerShell in the skill directory, then run:

```powershell
py -3 scripts\standalone_runner.py contract
py -3 scripts\standalone_runner.py demo --cognitive-features all --output-file demo.md --continuity-file demo.continuity.json
py -3 -m unittest discover -s tests -v
```

If the Python launcher `py` is unavailable but `python` is on `PATH`, replace `py -3` with `python`.

Paths containing spaces and Chinese characters are supported. Quote user-supplied paths in PowerShell:

```powershell
py -3 scripts\standalone_runner.py finalize --items-file '.\测试 数据\items.json' --output-file '.\输出 目录\今日简报.md'
```

## Generated command contract

Runner plans expose `command_argv` as the authoritative execution form. Process runners should pass this list directly to a subprocess API with shell execution disabled.

For human inspection, the runner also emits:

1. `command_hints.posix`
2. `command_hints.windows_powershell`
3. `command_hints.windows_cmd`

`command_hint` remains for backward compatibility and is selected for the host platform. All hint strings are display-only; do not pass them to `Invoke-Expression`, `cmd /c`, `sh -c`, or `shell=True`.

## Encoding and files

The CLI reconfigures standard output and standard error to UTF-8 before emitting Chinese JSON or Markdown. Generated JSON and Markdown files are written as UTF-8 without a BOM and with LF newlines so their hashes and diffs remain stable across macOS and Windows.

## Windows verification

Run the complete offline test suite from the repository root:

```powershell
py -3 -m py_compile scripts\standalone_runner.py
py -3 -m unittest discover -s tests -v
```

The cross-platform GitHub Actions workflow repeats these checks on `windows-latest` and `macos-latest` with Python 3.10 and 3.13. A local macOS pass validates the platform-independent logic and Windows simulations, but only a successful `windows-latest` job or Windows-host run counts as real Windows execution.

## Optional adapters

Vendored adapters live under `references\skills`. Invoke them through the `command_argv` generated by the runner whenever possible. If invoking one manually, use a repository-relative path:

```powershell
py -3 references\skills\anysearch\scripts\anysearch_cli.py doc
```

Network access, API credentials, browser login, and third-party adapter dependencies remain separate from core runner compatibility.

The optional README image-generation helper also has a PowerShell entrypoint:

```powershell
.\scripts\generate_readme_promo_images.ps1 -Concurrency 3
```

It is not part of the core briefing runtime. It requires the external Codex image-generation script, the local prompt file, and `OPENAI_API_KEY`; the CI job checks its PowerShell syntax but does not make a paid network call.
